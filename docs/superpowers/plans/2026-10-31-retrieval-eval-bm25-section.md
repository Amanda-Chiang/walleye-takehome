# Retrieval Evaluation, Dense Baseline, BM25 and Hybrid: Plan (Revision 2)

**Execution:** one coding agent, inline, in small checkpoints. Stop at each
checkpoint marked **Report** and show Amanda the result before continuing.

**Goal:** Build a larger development sample and a minimal retrieval-only
evaluator, reproduce the existing dense retrieval as a trusted baseline, then
add BM25 and hybrid retrieval through the existing `ComposedRetriever`, and,
if time permits, test section context as a controlled experiment. Decisions
about further techniques come from metrics plus reading failures, not from
fixed thresholds.

**Not in this iteration:** reranking, parent-child retrieval, generator
changes, the agentic loop, cross-paper questions, and the stashed
"combine scores per paragraph" change (`stash@{0}`).

## Changes From Revision 1

| Revision 1 | Revision 2 | Why |
| --- | --- | --- |
| BM25 before any baseline run | Dense baseline reproduced first (Task 3) | A trusted reference before new functionality |
| Near-miss counts over the union of all references | Missed paragraphs of the best-matching reference only | Matches the recall metric. Prevents counting a paragraph as "missed" when another accepted reference is fully retrieved |
| Adjacent / same-section / unrelated classification drives D10 | Report rank and section of each missed paragraph; no relation categories | Sharing a 30-paragraph "Experiments" section, or being adjacent, does not show that expansion would help |
| Hard thresholds decide D7, D9, D10 | Metrics plus manual reading; reranker headroom is necessary, not sufficient | Avoids committing to architecture because an arbitrary number was crossed |
| RRF ranks tied scores by paragraph position | Tied scores share one rank | Paragraphs with no BM25 match would otherwise get credit for appearing early in the paper |
| Shared index folder over a 20-question subset corpus | Shared index folder `.index-full` over the full corpus, with isolation checked once (Task 3) | All composed configs use the same corpus; their only artifacts are an identical `paragraphs.jsonl` and an embedding cache keyed by model settings and text. No new infrastructure for isolation. The full index also serves the chat page |
| Full code in the plan | Behavior, constraints and acceptance tests | The implementer writes the code |
| Separate code and docs commits; every test and lint command logged | One cohesive commit per feature; log meaningful experiments only | Less overhead |
| No end-to-end check | End-to-end check of the chosen retriever on the shipped 20 | Retrieval recall does not show whether answers and citations improve |

## Global Constraints

- Python 3.10 or later. Runtime code uses only the standard library.
- Readable code, pure functions where practical, deterministic tests, reuse
  of existing interfaces (`Scorer`, `TextView`, `Fusion`, config `"class"`).
- Docstrings: explain public interfaces and non-obvious behavior. The
  project's ruff config enforces pydocstyle on public functions, so trivial
  public helpers get a one-line docstring; private helpers (`_name`) need
  none.
- `ruff format` and `ruff check` clean on `src/qasper_agent` and `tools`;
  `python -m unittest discover -s tests` passes, with no API key, before
  each commit.
- Gold labels are read only after all retrieval has finished, and never by
  the retriever or the index.
- No QASPER test split. No changes to `tools/score.py` or
  `src/qasper_rag/validation/contracts.py`.
- API key: from `.env`, loaded per command with
  `set -a && source .env && set +a`. Never printed or committed.
- Commits: one cohesive commit per feature (code, tests, docs and config
  together), and one per experiment (results and log entry), on branch
  `build-rag-agent`.
- Logging: `EXPERIMENTS.md` records experiments and their outcomes (what
  ran, metrics, failures read, conclusions), not every test or lint run.
  New files go in the `docs/extensions.md` file table.

### Task 2: Minimal retrieval-only evaluator

**Files:** create `tools/retrieval_eval.py` and
`tests/test_retrieval_eval.py`; revise D7 and D10 in `docs/decisions.md`;
add the files to `docs/extensions.md`.

**Behavior:**
- CLI: `python tools/retrieval_eval.py --config C --index-dir D
  --questions Q --gold G --output O`.
- Builds the retriever named in the config the same way `load_service`
  does: `load_class(config.retriever, EmbeddingRetriever)(paragraphs,
  config.retriever, index_dir)`, with paragraphs from
  `<index_dir>/paragraphs.jsonl`.
- For every question, retrieves the top 20 paragraphs within the question's
  `paper_id`. Reads gold only after all questions are retrieved.
- For each answerable question (any reference with `abstain: false`):
  - `recall@k` for k in 5, 10, 20: the best recall over references, the
    same definition `tools/score.py` uses for recall@5.
  - **Best-matching reference:** the reference with the highest recall@5;
    ties go to higher recall@20, then to the earliest reference. The same
    rule applies at every depth, so diagnostics match the metric.
  - `missed`: the best reference's evidence paragraphs that are not in the
    top 5, each with its 1-based `rank` in the top 20 (or `null`) and its
    `section`.
  - `ranking`: the top-20 paragraph IDs, for reading failures.
- Output JSON: `config`, `answerable_questions`, `recall_at_5`,
  `recall_at_10`, `recall_at_20`, and `questions` (per question:
  `question_id`, `paper_id`, `recall_at_5`, `best_reference`, `missed`,
  `ranking`). Prints the summary without `questions`.
- Public pure functions to test: `recall_at(ranked, evidence_sets, k)`,
  `best_reference(ranked, evidence_sets)` (returns an index),
  `missed_paragraphs(ranked, evidence, paragraphs)`, and
  `evaluate(rankings, gold, paragraphs)`.

**Acceptance tests (`unittest`, no API):**
- `recall_at` matches `score.py`: ranked `[a, b, c]`, references
  `[[a, x], [c]]` gives 0.5 at k=1 and 1.0 at k=3.
- Best reference, the reviewer's case: references `[[p10], [p20]]` with
  `p10` retrieved and `p20` not gives recall@5 = 1.0 and **no** missed
  paragraphs.
- Tie rule: two references with equal recall@5 pick the one with higher
  recall@20; with equal recall at both depths, the first one.
- Missed paragraphs report rank (6–20, or `null` beyond 20) and section.
- Unanswerable questions are skipped.
- End to end on `tests/fixtures/` with a composed retriever and the fake
  `KeywordScorer` from `tests/test_composed_retriever.py`: writes JSON with
  `answerable_questions == 1` and `recall_at_5 == 1.0`.

**Decision-log edits in the same commit:**
- D7: recall@20 well above recall@5 is *headroom*, a necessary sign, not a
  decision. If headroom appears, a later iteration may test a reranker on a
  representative subset and keep it only if retrieval improves enough to
  justify its latency and complexity.
- D10: no automatic choice. Missed-paragraph ranks and sections, plus
  reading failures, inform whether any expansion is worth testing later.
  Adjacency or a shared section alone does not show expansion would help.

**Commit:** "Add retrieval-only evaluation (recall@5/10/20, rankings,
best-reference misses)".

### Task 4: BM25 and hybrid retrieval through existing composition

**Files:** create `src/qasper_agent/retrieval/bm25.py`, `tests/test_bm25.py`,
`config/composed-bm25.json`, `config/composed-hybrid.json`; modify
`src/qasper_agent/retrieval/fusion.py` and its tests; update
`docs/extensions.md`.

**Behavior:**
- `BM25Scorer(settings, index_dir)` implements the existing `Scorer`
  interface: Okapi BM25, `k1` default 1.5 and `b` default 0.75 from
  settings, IDF over all indexed units, standard library only. Paragraphs
  with no query term score 0.
- `tokenize(text)`: lowercase, split on non-alphanumerics, drop a plural
  "s" (not for words of 3 letters or fewer, nor words ending in "ss"), so
  "baselines" matches "baseline" (a run 001 miss).
- **Tie-aware RRF:** `ReciprocalRankFusion` gives equal scores the same
  rank, the best position of the tied group. Paragraphs that BM25 does not
  match all share one rank, so their position in the paper earns them no
  credit. Dense scores almost never tie, so dense-only rankings, and
  therefore parity with the starter, are unchanged.
- `composed-bm25.json`: BM25 only (no API). `composed-hybrid.json`: BM25 +
  dense with RRF `k` = 60. Same generator section as `composed-dense.json`.

**Acceptance tests (`unittest`, no API):**
- Tokenizer: `"Our Baselines: TransE, 82% F1."` gives
  `["our", "baseline", "transe", "82", "f1"]`; `"is class gas"` is
  unchanged.
- BM25: a matching unit beats a non-matching one; no overlap scores 0; a
  rare term outweighs a common one; a shorter unit beats a longer one with
  the same term count; scores come back for exactly the requested
  candidates.
- RRF ties: `fuse([[0, 0, 0, 5]])` ranks unit 3 first and gives units 0–2
  **equal** fused scores. Existing RRF tests still pass.
- Hybrid integration (fake dense scorer with fixed scores plus real BM25):
  a paragraph that dense ranks first and BM25 does not match is **not**
  pushed down by non-matching paragraphs that come earlier in the paper.
- Paper filter: with two papers indexed, hybrid retrieval for paper A never
  returns paper B's paragraphs, even when B matches the query better.
- The existing dense parity test still passes.

**Experiment:**
1. Index each config into `.index-full` (BM25 adds nothing to the folder;
   hybrid reuses the dense vectors from the cache, so no new embeddings).
   Confirm the folder's file list is unchanged.
2. Evaluate both on `data/eval-120`, writing `experiments/runs/003-bm25.json`
   and `003-hybrid.json`.
3. Compare with 002: recall@5/10/20, plus per-question wins and losses at
   recall@5 against dense. Read at least 10 failures of the best config and
   every question where hybrid is worse than both single scorers.

**Commits:** "Add BM25 scoring and hybrid retrieval with tie-aware RRF"
(code, tests, configs, docs); then "Compare BM25 and hybrid with the dense
baseline (003)" (results, entry 003). **Report.**
